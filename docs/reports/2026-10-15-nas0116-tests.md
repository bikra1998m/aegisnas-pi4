## Failures, repairs and test limits

- Real PostgreSQL initially rejected the unquoted `user` audit column, then integer booleans in template/seed SQL. Quoted identifiers, TRUE/FALSE literals and dialect-aware audit ordering fixed the exercised paths. Both live PostgreSQL versions subsequently passed. Other runtime queries still need PostgreSQL coverage; NAS-0008 is reopened.
- A 60-second diagnostic SQLite migration test timed out in Windows `FlushFileBuffers`; the same test passed in the full suite with its existing longer deadline. Storage counters sampled 58.85 ms average transfer latency and queue length 9. This suggests contention but does not establish a root cause.
- The first VM toolchain download failed with a TLS timeout; its first full suite hit the 2,400-second driver limit and its first PostgreSQL invocation hit 900 seconds during dependency setup. Earlier vet/build/API/fuzz runs subsequently completed. SSH/HTTP later became unreliable; the user authorized a graceful VMware reboot, which succeeded. Final runs are recorded separately. No timed-out run is relabeled as passing.
- The first follow-up npm SBOM failed because optional WASM transitive entries were missing from the lockfile. Regenerating the lock in an empty directory, followed by clean npm install, SBOM generation and UI build, fixed it. The original scan and its source-change blocker remain retained.
- An initial `go mod download all` failed on TLS/DNS/network errors. Its explicit retry completed successfully. A final collector was run after dependency warm-up.
- The second collector could not find the pinned Go scanner binaries (exit 127) because their local tools directory was absent from PATH. The failure blocked as designed; a separate complete retry with the explicit scanner path is recorded.
- The >500 kB Vite chunk warning remains (final main JS 1,554.76 kB, gzip 253.04 kB). No code-splitting performance claim is made. Tailwind 4 and React Router 7 require the documented newer toolchain/browser baseline.
- `radclient` returned exit 1 with an observed Access-Reject: that is the expected negative authentication outcome, not a successful positive login. No account or live deployment data was created for that probe. The deployed readiness JSON reported `ready: false`, `status: blocked`.
- Acceptance Go tests use local SQLite and mock LDAP/RADIUS helpers. The actual FreeRADIUS negative packet test is listed separately. PostgreSQL tests use disposable trusted loopback connections; TLS verify-full, backup/restore, replication and outage behavior were not certified.
- Security evidence is diagnostic for the uncommitted snapshot, not release admission. Reports and metadata generated afterward change the full source fingerprint; a clean committed CI rescan is required for a candidate.
- Final source changes after the Ubuntu full suite were a whitespace-only SQL edit, bootstrap toolchain defaults and roadmap/report metadata. Bootstrap now reads its Go version from `go.mod` and uses Node 22; shell syntax was checked, but the system-installing bootstrap was not executed against the existing VM.
- Test downloads/build caches increased VM disk use; the final filesystem check showed 4.1 GiB available (89% used). The isolated source/evidence and caches were retained for review, rather than deleting evidence or unrelated VM data.
